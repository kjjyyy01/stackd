## 실행 규칙

- **프로덕션(stackd.kr)에서만** — 로컬·프리뷰는 대상 아님. 실제 유저가 겪는 것과 같은 지연·캐시·WAF를 겪어야 한다
- **모바일 1회 + 데스크톱 1회** 각각 순회 — 한국 모바일 주력은 iOS Safari
- 막히면 **고치지 말고 기록만** 한다. 순회 중 수정하면 나머지 구간을 못 본다
- 순회 중 발견은 전부 아래 템플릿으로 기록 → 순회 종료 후 심각도 분류
- ⛔ **신기능 개발 금지**(판정일까지) — 마찰 기록은 backlog 입력이지 착수 지시가 아니다

## 순회 시나리오

각 항목은 "했다/안 했다"가 아니라 **막힌 지점이 있었는가**로 판정한다.

### A. 만들기 (비로그인, SCR-001 → SCR-003)

1. [ ] `stackd.kr` 진입 — 첫 화면만 보고 이 서비스가 뭘 하는지 말할 수 있는가
2. [ ] 히어로 0번 카드에서 "상세 보기"까지 도달
3. [ ] 빌더에서 상황 입력 → 단계 3개 이상 추가 (카탈로그 검색 1회 + 직접 입력 1회 둘 다)
4. [ ] 도구가 카탈로그에 없을 때 직접 입력으로 넘어가는 흐름이 자연스러운가
5. [ ] `/card` 미리보기 도달 — 카드가 입력한 내용과 일치하는가

### B. 저장 (로그인 게이트, SCR-003)
