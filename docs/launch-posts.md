## 1. GeekNews — 기술 커뮤니티 톤 (구현 판단 중심)

**제목 후보** (하나 고른다)
- Stackd — 내 AI 워크플로우를 카드 한 장으로 공유하는 사이트를 3주 만에 만들었습니다
- 도구는 아는데 어떻게 쓰는지 모르겠어서, 남들 워크플로우를 카드로 모으는 곳을 만들었습니다

**본문**

Claude Code 같은 도구를 쓰다 보면 "이 skill·MCP가 좋다"는 정보는 넘치는데, 실제로 어떤 상황에서 어떤 순서로 붙여 쓰는지는 잘 안 보입니다. 그래서 개발자가 자기 워크플로우(상황 + 순서 있는 단계 + 도구)를 카드 한 장 + 상세 페이지로 만들어 공유하고, 라이브러리에서 남의 예시를 보는 사이트를 만들었습니다.

https://stackd.kr/?utm_source=geeknews&utm_medium=community

만들기·보기는 로그인 없이 되고, 저장할 때만 GitHub 로그인입니다. 카드는 PNG로 저장하거나 링크로 공유합니다.

**어떻게 만들었나**

혼자 3주(실작업 20일 + 버퍼 2일)로 잡고, 이 일정 자체를 첫 번째 카드로 만들었습니다:
https://stackd.kr/card-detail/934c9228?utm_source=geeknews&utm_medium=community

기술 쪽에서 남길 만한 판단 몇 가지:

- **Next.js 16 App Router + Supabase(Auth·Postgres·RLS)**. 콘텐츠는 전부 서버 렌더링 — `"use client"`는 애니메이션 래퍼에만. JS 없이도 카드 텍스트가 보이는 게 조건이었습니다.
- **카드 4:5 비율은 숙고가 아니라 실측으로 정했습니다.** 상한 케이스(제목 30자·단계 8개·메모 60자)를 px로 재서 확정. 모바일에서 카드가 컨테이너를 넘치던 버그는 Safari에서만 났고, 원인은 `transform: scale()`이 레이아웃 박스를 안 줄인다는 걸 잊은 것.
- **카드 전환이 느린 원인이 코드가 아니라 Vercel 함수 리전이었습니다.** iad1 → icn1로 옮기니 해결. 프로파일링 전에 인프라부터 의심했어야 했습니다.
- **런칭 준비에서 가장 오래 걸린 건 OG 메타.** Next의 `openGraph`는 하위 라우트가 선언하면 상위와 병합이 아니라 교체라서 site_name·locale이 통째로 사라졌습니다. 3라운드 만에 잡았습니다.
- 프로덕션 LCP 824ms, Lighthouse a11y·SEO·BP 100. 테스트는 도메인 로직만 31개, E2E는 핵심 플로우 1개.

AI 도구 쪽은 superpowers를 유일한 오케스트레이터로 두고, 기획은 make-plan → make-prd로 ID 스킴(SCR/BR/EVT…)을 박아서 구현 중 스코프가 조용히 흔들리는 걸 막았습니다. 구현 구간엔 YAGNI 강제(ponytail)를 상시로. 일정은 4번 조정했는데 런칭일은 한 번도 안 밀렸습니다 — 버퍼를 런칭 직전에 둔 덕입니다.

v1은 Claude Code 생태계 한정이고, 검색·필터·포크는 일부러 뺐습니다(백로그). 런칭 후 2주 데이터로 지속 여부를 판정할 예정이라, 써보시고 워크플로우 하나 올려주시면 판정에 직접 도움이 됩니다.

피드백은 사이트 푸터의 문의 창이나 이 글 댓글로 부탁드립니다.

## 2. 디스콰이엇 — 메이커 톤 (과정 + 제품)

**제목 후보**
- 혼자 3주 만에 기획→출시까지: 내 AI 워크플로우를 카드로 공유하는 Stackd를 런칭했습니다
- "도구는 아는데 어떻게 쓰는지 모르겠다" — 실제 개발자들의 AI 워크플로우 카드 모음, Stackd

**본문**

안녕하세요. 개발자들이 자기 AI 워크플로우를 카드 한 장으로 만들어 공유하는 **Stackd(스택드)** 를 오늘 런칭했습니다.

https://stackd.kr/?utm_source=disquiet&utm_medium=community

**왜 만들었나**

Claude Code 같은 AI 코딩 도구는 "뭘 쓰면 좋다"는 정보는 많은데, 실제 개발자가 **어떤 상황에서 어떤 순서로** 쓰는지 예시가 거의 없습니다. GitHub에 설정 파일 올리는 분들은 많지만 읽는 사람이 없죠. 그래서 상황 + 단계 + 도구를 카드로 만들고, 라이브러리에 모아서 "비슷한 상황이면 이렇게 써봐"를 나누는 곳을 만들었습니다.

**무엇을 할 수 있나**

- 워크플로우 빌더: 상황 → 단계(도구 + 메모) → 개발 스택 태그. 카탈로그 268개에서 고르거나 직접 입력
- 카드 미리보기 → GitHub 로그인으로 저장 → 상세 페이지 + PNG 저장 + 링크 공유
- 라이브러리에서 다른 개발자의 워크플로우 구경

첫 카드는 이 프로젝트 자체입니다 — "클로드 코드와 서브에이전트로 3주 만에 서비스 출시하기":
https://stackd.kr/card-detail/934c9228?utm_source=disquiet&utm_medium=community

**3주 동안 있었던 일**

- Day 1에 아이디어를 세 번 뒤집고 확정했습니다. 앞의 두 개는 킬 크라이테리아(런칭 후 2주 뒤 지속/중단 기준 3줄)를 못 넘겨서 버렸습니다.
- Day 3에 스코프를 한 번 더 뒤집었습니다. "스택 목록 자랑"에서 "워크플로우 공유"로 — 백엔드 없이 가려던 계획이 Supabase로 바뀌었습니다.
- 일정을 4번 조정했는데 런칭일(9/8)은 8/19 이후 한 번도 안 움직였습니다. 버퍼 2일을 런칭 직전에 두고, 지연은 앞에서 흡수하는 구조였습니다.

- 넘치는 아이디어는 전부 `backlog.md`로 보냈습니다. 검색·필터·포크·i18n은 그래서 지금 없습니다.

혼자 했지만 혼자는 아니었습니다 — 기획·PRD·구현·리뷰·기록 대부분을 Claude Code 위에서 돌렸고, 그 워크플로우가 위 첫 카드입니다.

런칭 후 2주 데이터로 계속할지 정할 예정이라, 워크플로우 하나 만들어 올려주시면 판정에 직접 반영됩니다. 피드백은 댓글이나 사이트 푸터 문의 창으로 주세요.
