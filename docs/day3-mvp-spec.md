## 제품 한 줄

개발자가 **자기 Agentic workflow — 어떤 상황에서, 어떤 순서로, 어떤 도구(skills·plugins·MCP·agents)를 어떻게 쓰는지 —** 를 **카드 한 장(요약) + 상세 페이지(설명)** 로 만들어 링크로 공유하고, **갤러리**에서 다른 개발자의 워크플로우 예시를 본다. 한국어 UI · 카드 라벨/도구명 영어 · 사용자 텍스트는 입력 언어 그대로 · **저장 시점에만 GitHub 로그인**.

**만든 이유 (2026-08-16 재정의)**: agent 도구를 *뭘* 쓰면 좋은지는 알려져 있는데 *어떻게 응용해서* 쓰는지 예시가 적다. 여러 사람이 실제로 어떻게 쓰는지 — "나는 이런 상황에 이렇게 써, 비슷하면 써봐" — 가 필요하다. Stackd는 그 예시를 카드로 만들고 모으는 곳이다. (자랑·명함이 아니라 **공유·권유**. 명함은 카드 톤(고급감·여백)에만 남는다.)

**생태계 범위**: v1은 Claude Code 생태계 한정 (카탈로그·카피). 개발 스택(React·Next.js 등)은 "어떤 프로젝트에서 쓰는 워크플로우인지" **컨텍스트 태그**로 포함.

## 핵심 플로우

홈 진입 → 워크플로우 작성(상황·단계·태그·닉네임) → 카드 미리보기(`card_create`) → **저장** (미로그인 → GitHub OAuth → 복귀, 초안 보존) → 공개/비공개 선택(기본 공개) → 상세 페이지 `/w/{id}` → PNG 다운로드 / 링크 복사(`card_share`) → 받은 사람이 상세를 보고 "나도 만들기"(`utm_source=card`) 또는 갤러리 탐색 → 루프.

## SCR 목록 (6개 — 상한 7 이내)

> ID는 v1과 연속. **SCR-002(파싱)는 결번**(컷). 컷 순서(Day 11 판정): ① SCR-006 갤러리 ② SCR-007 수정 기능(삭제만 남김) ③ 소속·역할 필드.

### SCR-001 홈 (랜딩 + 워크플로우 빌더) `/`
- **목적**: 가치 전달 + 작성 시작. 랜딩·빌더 통합 유지
- **구성**: 히어로(h1 **TBD — 사용자 작성 대기**, 부제 "개발 스택과 AI 스택, 카드 한 장에 담아 링크로"(재검토 가능), 예시 카드 1장 = 0번 카드) → 빌더
  - **제목** (1~40자) / **상황 요약** (1~80자, 카드 한 줄) / **상황 상세** (0~1,000자, 상세 페이지)
  - **단계** 2~8개, 순서 변경(위/아래): 각 단계 = 도구(카탈로그 검색·선택 or 직접 입력 이름+카테고리) + **한 줄 메모**(0~60자, 카드) + **상세 설명**(0~500자, 상세 페이지)
  - **개발 스택 태그** 0~4개 (카탈로그 language/framework/tool)
  - 닉네임(1~10, 필수) · 소속/역할(0~20, 선택) — v1 BR-003/008 유지
  - 로그인 상태면 헤더에 "내 카드"; 수정 모드(`/?edit={id}`, 소유자만)면 기존 값 로드
- **상태**: 단계 <2 → CTA 비활성 + 안내 / 초안 존재 시 "이어서 작성" 안내
- **컷 여부**: 불가

### SCR-003 카드 미리보기 · 저장 `/card`
- **목적**: 카드 비주얼 결판 + 저장 게이트. `card_create` 발생점 (진입 && 단계 ≥2, 로그인 전)
- **구성**: 요약 카드 실시간 렌더(제목·닉네임/소속·상황 한 줄·단계 번호 목록(도구명 + 메모)·태그·워터마크) + 액센트 컬러 2~3택 + **공개/비공개 토글**(기본 공개) + [저장]
- **저장 흐름**: 미로그인 → 초안 보존 → GitHub OAuth → `/card`로 복귀 → 저장 실행 → `/w/{id}` 이동. 로그인 상태면 즉시 저장
- **상태**: 저장 실패(네트워크·RLS) 토스트 + 재시도 / 오프라인 시 저장 비활성
- **컷 여부**: 불가

### SCR-004 워크플로우 상세 `/w/{id}`
- **목적**: 확산 착지점 + 긴 설명. `card_share` 발생점
- **구성**: 요약 카드 렌더(SCR-003 컴포넌트 재사용, 서버 렌더) → 상황 상세 전문 → 단계별 상세 설명(줄바꿈 유지, 마크다운 없음) → 작성자(닉네임·소속) → [PNG 다운로드] [링크 복사] → "나도 만들기" CTA(`/?utm_source=card&utm_medium=share`) → 신고 dialog. **소유자면** 수정·삭제·공개 토글
- **OG**: `generateMetadata` + `/api/og?id=` (DB 조회, 공개 카드만) — 카톡·X 미리보기에 그 카드
- **접근**: 공개 = 누구나·index / 비공개 = 소유자만 (타인 접근 시 404) / `hidden`(모더레이션) = 소유자 외 404
- **컷 여부**: 불가

### SCR-005 법적 문서 `/privacy` · `/terms`
- 개인정보처리방침(GitHub 이메일·핸들 수집, GA4, 삭제·탈퇴), 이용약관(게시물 책임·신고·삭제), 분석 고지 통합. 정적 2페이지 — Day 4~11 내 제작
- **컷 여부**: 불가 (법적)

### SCR-006 갤러리 `/gallery`
- **목적**: 예시가 모이는 곳 — 만든 이유의 실체
- **구성**: 공개 카드 최신순 목록(요약 카드 썸네일 + 제목·닉네임) + 더 보기(페이지네이션) → 클릭 `/w/{id}`. 검색·필터·정렬·좋아요 없음(backlog — 30장 넘으면 필터 고려)
- **시드**: 런칭 전 본인 워크플로우 **3~5장** (빈 갤러리 방지 — 콘텐츠 소요 ②)
- **컷 여부**: **Day 11 컷 1순위** — 카드는 호스팅되므로 링크 공유만으로 v1 성립

### SCR-007 내 카드 `/me`
- 로그인 필수. 내 카드 목록(공개/비공개 표시) · 수정(→ SCR-001 로드) · 삭제(확인) · 공개 토글 · 로그아웃 · **탈퇴**(계정+카드 전부 삭제 — 개인정보 삭제권)
- **컷 여부**: 수정만 컷 가능(2순위), 삭제·탈퇴는 법적으로 불가

## 데이터 모델 골자 (PRD-05에서 확정)

**Supabase Postgres, 테이블 2개 + auth.users**

`workflows`
| 필드 | 타입 | 제약 |
|---|---|---|
| id | text PK | 짧은 id 8자(nanoid류) — `/w/{id}` |
| user_id | uuid FK auth.users(on delete cascade) | 소유자 |
| title | text | 1~40 |
| summary | text | 1~80 (카드 한 줄) |
| situation | text | 0~1,000 |
| steps | jsonb | `[{tool:{name,category}, note(≤60), detail(≤500)}]` 2~8개 |
| dev_stack | jsonb | `[{name,category}]` 0~4 |
| nickname / role | text | 1~10 / 0~20 |
| accent | text | 슬러그 |
| is_public | bool | 기본 true |
| hidden | bool | 기본 false — 모더레이션(대시보드에서만) |
| created_at / updated_at | timestamptz | |

`feedback` — id, type(report/contact/feedback), workflow_id(nullable), body(≤500), created_at. insert 누구나, select 정책 없음(대시보드 전용 = v1 Admin).

**RLS**: workflows select = `is_public and not hidden` or `auth.uid()=user_id` / insert·update·delete = 소유자. feedback insert = anon 허용.

**카탈로그** `data/catalog.json` 정적 유지 (v1 스키마·enum 7종 그대로).

**클라이언트**: 초안 = localStorage `stackd:draft`(전 필드 + edit id) — OAuth 왕복·새로고침 보존.
