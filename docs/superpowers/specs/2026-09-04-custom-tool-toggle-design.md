# 커스텀 도구 토글 설계 (custom tool toggle)

- 일자: 2026-09-04 (런칭 D-4, 버퍼 1일차)
- 상태: 설계 승인 완료 → 구현 계획 대기
- 요청: 단계에서 `skill·plugin·mcp·agent`를 고를 때 "공개된 도구가 아님"을 표시하는 토글
- 분류: **Architectural** — `WorkflowInput.steps[].tool` 타입 변경이 빌더·서버 액션·OG 렌더 3곳에 동시에 걸린다 (`lib/limits.ts:1`)

## 배경

`docs/prd/01_제품개요.md:17`이 정한 제품 목적은 *"여러 개발자의 실제 워크플로우가 카드로 모이면, 비슷한 상황의 개발자가 **그대로 써볼 수 있다**"* 이다. 그런데 지금은 어떤 단계가 재현 가능한지를 표시할 자리가 없다.

실제로 프로덕션 0번 카드(`934c9228`)의 6단계 메모가 이 공백을 산문으로 메우고 있다 — *"직접 만든 개인 스킬이다(카탈로그엔 없음 — git add·commit·push를 Conventional Commits로 감싼 것)"*. 필드가 없어 60자 메모 한도를 설명에 쓴 것이고, 그 카드가 런칭 포스트의 대표 콘텐츠다. 계획 동결(`PLAN.md:285`)이 허용하는 *"실행 중 실제로 발견된 문제의 반영"* 에 해당한다.

## 확정된 결정

| # | 질문 | 결정 |
|---|---|---|
| 1 | 토글의 의미 | **가용성** — "공개돼 있지 않아 남이 그대로 못 씀". 저작(who made it)이 아니다 |
| 2 | 노출 조건 | **직접 입력한 도구에만**. 카탈로그 선택 도구는 정의상 공개이므로 토글 없음 |
| 3 | 카드 표시 | **텍스트 라벨** `custom` (기호 마커·rail 변형 기각) |
| 4 | 범위 | 카드 표면·OG 포함 전체 (A안) |

결정 1의 근거: 기획서가 *"자랑·명함이 아니라 공유·권유"* 로 방향을 못 박았다(`01_제품개요.md:17`). 저작 표시는 자랑 쪽이고, 가용성 표시는 권유 쪽이다.

결정 2의 근거: 카탈로그 268개(`history.md:228`에서 확정)는 *"공식 마켓플레이스 + awesome 리스트"* 에서 수집한 것이라(`day1-decisions.md:54`) **카탈로그에 있다 = 공개돼 있다**가 정의상 성립한다. 카탈로그 도구에 토글을 노출하면 "카탈로그에 있는데 커스텀"이라는, 데이터로는 가능하지만 뜻이 성립하지 않는 상태를 허용하게 된다.

결정 3의 근거: 이 기능의 목적은 읽는 사람에게 "이 단계는 따라할 수 없다"를 알리는 것이다. 범례를 봐야 해독되는 마커는 목적을 절반만 달성하고, 카드가 SNS에서 이미지로 돌 때는 범례가 함께 읽히지 않는다.

## 데이터 모델

```ts
// lib/limits.ts
steps: { tool: { name: string; category: Category; custom?: boolean }; note: string; detail: string }[]
```

**`custom`은 선택적 필드다.** 기존 6장의 `steps` jsonb에 키가 없어도 유효하므로 **DB 마이그레이션 0건**. 값이 없으면 `false`로 읽는다.

`supabase/schema.sql`은 손대지 않는다 — `steps`는 `jsonb`이고 CHECK는 배열 길이만 본다(`schema.sql:15-17`).

### 초안 버전

**`lib/draft.ts`의 `VERSION`은 2로 유지한다.** `isDraft()`가 최상위 필수 키만 검사하고 `tool` 내부는 보지 않으므로(`draft.ts:23-28`) 기존 초안이 그대로 유효하다. 버전을 올리면 사용자들이 쓰던 초안만 폐기되고 얻는 것이 없다.

## 검증 (BR-026 신설)

`validateWorkflow`가 강제하는 것:

1. `custom`이 있으면 `boolean`이어야 한다. 아니면 `ERR-BLDR-008`
2. `custom === true`는 `category ∈ {skill, plugin, mcp, agent}`일 때만 허용. `language·framework·tool`이면 `ERR-BLDR-008`
3. `custom === false`는 저장하지 않고 키를 지운다 — 기본값을 굳이 적재하지 않는다(기존 6장과 같은 모양 유지)

### 강제할 수 없는 것 (명시적 한계)

**"카탈로그에 있는 도구는 `custom`일 수 없다"는 서버가 막지 못한다.** 카탈로그는 클라이언트 정적 JSON(`data/catalog.json`)이라 서버 검증 경로에 없다. 결정 2는 **UI 계약**이지 서버 불변식이 아니며, API를 직접 호출하면 모순 데이터가 들어갈 수 있다.

이를 해소하려면 카탈로그를 서버로 올려야 하는데(DB 테이블 또는 서버 번들 포함), 런칭 D-4에 늘릴 표면이 아니다. **한계를 BR-026에 명시하고 넘어간다.** 실제 피해는 "잘못 표시된 배지" 한 개이고 데이터 손상이나 권한 문제로 번지지 않는다.

## 입력 UI (SCR-001)

- `EL-HOME-025` 신설 — 단계 편집 영역의 체크박스
- **노출 조건**: 해당 단계의 도구가 직접 입력이고 `category ∈ {skill, plugin, mcp, agent}`
- 기본값 꺼짐
- **"도구 교체 시 값 리셋" 규칙은 넣지 않는다** (2026-09-04 계획 수립 중 확인). 빌더에 단계의 도구를 교체하는 UI가 없다 — 도구명·카테고리는 읽기 전용이고 바꾸려면 단계를 지우고 다시 추가해야 한다. "화면에 없는 값이 저장되는" 경로가 존재하지 않으므로 방어 코드를 넣으면 도달 불가능한 분기만 남는다
- 카피 `CPY-HOME-060`: 체크박스 라벨 — 한국어 UI 규칙 적용

### 노출 조건을 무엇으로 판정하는가 (2026-09-04 계획 수립 중 수정)

**카탈로그 미등재 여부로 판정한다** — `lib/catalog.ts`의 `isCatalogTool(name)`.

당초 설계는 "툴 피커의 `method: catalog | manual` 신호를 빌더 로컬 상태로 들고 있는다"였으나, **로컬 상태는 초안 복원·`?edit=` 로드·새로고침에서 사라진다.** 그러면 직접 입력으로 추가한 단계의 토글이 재진입 후 없어져, 사용자가 켤 수도 끌 수도 없는 값이 저장된 채로 남는다.

카탈로그 조회 판정은 이 문제가 없고 결정 2의 의미와 정확히 일치한다("카탈로그에 있다 = 공개돼 있다"). 실측: 카탈로그 268개에 이름 중복 0건이라 `name`이 안전한 키이고, 0번 카드의 `commit-push`는 미등재·`superpowers`는 등재로 의도한 대로 갈린다.

`method` 신호는 기존대로 GA4 `step_add`에만 쓰고 버린다(`workflow-builder.tsx:113`) — 계측 의미가 달라서 겸용하지 않는다.

## 표시

카드 라벨은 영어라는 규칙(`01_제품개요.md:21`, 실제로 `WORKFLOW`·`STACK`)에 따라 **배지 문구는 `custom`**, 상세 페이지의 설명 문장만 한국어.

| 표면 | 파일 | 처리 |
|---|---|---|
| 카드 | `components/workflow-card.tsx:80` | 도구명 뒤 `custom` 배지. 도구명 `min-w-0` + 배지 `shrink-0` → **도구명 쪽이 말줄임되며 폭을 흡수** (메모의 `line-clamp-1`과 같은 전략) |
| 상세 | `app/card-detail/[id]/page.tsx` | 같은 배지 + 한국어 설명 1줄 (`CPY-WF-017`) |
| OG | `app/api/og/route.tsx` | 같은 배지 |

### OG 주의사항 (Day 17 재발 방지)

`route.tsx:55`의 `monoText`가 **폰트 서브셋을 문자 단위로** 만든다. 배지에 쓰는 문자가 이 문자열에 없으면 **OG에서만 글리프가 비어 보인다** — 빌드도 통과하고 다른 화면은 멀쩡하다. `custom` 7글자를 `monoText`에 반드시 더한다.

OG는 `slice(0, 3)`으로 앞 3단계만 그린다(`route.tsx:48`). 4단계 이후의 `custom`은 이미지에 나타나지 않는다. **기존 동작이며 바꾸지 않는다** — 4개째부터 1072px을 넘어 찌그러진다는 실측 근거가 이미 주석에 있다.

- `data/catalog.json` 268개 데이터
- `supabase/schema.sql`
- 기존 6장의 저장된 데이터 (읽기 시 `custom` 없음 → `false`)
