# 3주 출시 마스터 플랜 (Master Launch Plan)

> 목표: 웹 서비스를 3주 안에 실서비스로 출시하고 마케팅까지 진행
> **이 문서는 우선순위를 미리 확정하지 않는다.** 중점 품질 축, 충돌 시 승패 규칙(우선 원칙), 유입 전략(SEO·커뮤니티·입소문 등)의 우선순위는 전부 **무엇을 만들지 확정된 뒤 Day 1에 결정**한다. 서비스가 무엇이냐에 따라 우선순위는 완전히 달라진다.
> 문서에 고정으로 남는 것은 우선순위가 아니라 **구현 위생 기준**(서버 렌더링 보존, 시맨틱 마크업, 정렬 축, 반응형)뿐이다 — 이것들은 어떤 서비스든 지금 지키면 비용이 0에 가깝고 나중에 고치면 비싸다.
> 원칙: 이 문서가 유일한 계획서. 추가 아이디어는 전부 `backlog.md`로.
> **기간 산정**: 실작업일 N=20 (Day 1~20, 1.0일/일 가정) = 기획 3 + 구현-기능 **8** + 폴리싱 **2** + 게릴라·리뷰 **1** + 출시 준비·점검·게시·런칭 6 / 버퍼 잔량: **2일** (2026-08-22 버퍼 소진 2 — 어떤 작업도 배정 금지)
> **조정 이력**: `2026-08-16` 기간 20→20 실작업일(달력 +2일: Day 3 지연 2일 상쇄), **지렛대 0·2·3 적용**, 버퍼 잔량 0, 사유: Day 3 지연(8/14→8/16) + Day 3 재판정으로 v1 스코프 확대(백엔드 Supabase Auth+DB·갤러리·상세 페이지·워크플로우 빌더 재작업 → 구현 +2일). 지렛대 2로 폴리싱 3→2일: 중점 축 목표를 "히어로 > 페이지 전환"까지로 하향(스크롤·마이크로는 backlog). **조정 1회차**
> **조정 이력 2**: `2026-08-17` 달력 +1일 (Day 3가 8/17까지 — 지연 누적 3일), 지렛대 없음(구간 길이 전부 유지, 런칭·게시를 같은 날 오전으로 결합), 버퍼 잔량 0, 사유: 재판정 grill·기획서 v2가 8/16을 넘김. **조정 2회차**

## 운용 원칙 요약

1. **오케스트레이터는 superpowers 1개** — omc는 발동 조건 충족 시에만 교대, 동시 활성화 금지
2. **ecc는 플러그인이 아니라 부품 창고** — 본체 영구 off, 필요 컴포넌트만 추출
3. **Phase 전환 = 이전 스킬 off까지** — 전 구간에서 동시 활성 스킬 최소화
4. ⚠️ **지정 스킬 호출은 변경 규모로 판단** — 각 Day 표의 "활성화 스킬" 열·상시 규칙에 지정된 skill·plugin·MCP는 아래 3등급으로 적용한다.
   - **단순 수정** (UX 문구, 에러 메시지, 단일 값 변경): 스킬 호출 없이 대상 파일만 지정해 직접 편집.
   - **중간 수정** (AC 추가, 검증 규칙 변경): 스킬 호출 없이 **해당 파일만 로드**해 ID 형식·제약 준수를 확인. 템플릿 대조와 문서 전체 정합성 검사는 생략.
   - **구조 변경** (화면 추가·삭제, 데이터 모델 변경, API 계약 수정, 스코프 변경): **풀 스킬 + 정합성 검사** 필수 — 기획서 = make-plan, PRD = make-prd, 스코프 = /grill-me, 설계 판단 = sequential-thinking. 스킬을 건너뛴 구조 변경은 정합성 미검증으로 간주하고 해당 스킬로 재검증한다.
