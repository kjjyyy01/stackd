# 15 분석 및 추적 — EVT SSOT (GA4 명세)

> 킬 크라이테리아 판정(H-01·02, 런칭+14일 = 9/17)은 전부 **GA4** 위에서 이뤄진다. DB(Supabase)는 게시물 저장소이지 분석 저장소가 아니다 — 판정에 DB 카운트를 쓰지 않는다(총 사용자 분모가 GA4에만 있음). DB의 저장 수는 보조 관찰 지표로만.
> 설정: 측정 ID는 `NEXT_PUBLIC_GA_ID` 환경변수.

## 공통 규칙

- 네이밍: snake_case, 이벤트명·파라미터명 ≤40자, 값 ≤100자, 예약 접두사 금지
- ⚠️ 규격 이탈 신고: 스킬 스펙의 "과거형" 규칙 대신 **Day 1 확정명(`card_create`/`card_share`) 유지** — 킬 크라이테리아·PLAN이 이 이름으로 동결됨
- PII 금지 — 자유 텍스트 파라미터는 `item_name`(도구명)뿐. GitHub 핸들·이메일·워크플로우 제목·상황 텍스트는 **수집하지 않는다**. `workflow_id`(8자 랜덤)는 PII 아님 — 수집
- `page_view`는 향상된 측정 자동 수집 — `/workflows`·`/card-detail/{id}` 조회는 page_view로 충분, 커스텀 조회 이벤트 금지. "나도 만들기" 클릭은 UTM이 계수. **커스텀 이벤트는 아래 7종이 전부**
- 발화 실패는 침묵 — 트래킹 에러가 UX를 막지 않는다
- 결번: ~~EVT-PARSE-001~~(파싱 컷). v1 `stack_add`는 `step_add`로 개명(발화 의미가 바뀜 — 단계 추가)

## 이벤트 카탈로그

| EVT-ID | 이벤트명 | 발화 시점 (화면) | 파라미터 | 측정 대상 |
|---|---|---|---|---|
| EVT-BLDR-001 | `step_add` | 단계에 도구가 확정되는 순간 (SCR-001) — 삭제·재추가 미측정 | `method`: `catalog`\|`manual` / `item_category`: enum 7종 (BR-004) / `item_name`: 도구명 | 중간 퍼널 · 도구 인기 |
| EVT-CARD-001 | `card_create` | **`saveWorkflow` 성공 — 신규 저장(`mode=create`)만** (SCR-003). "카드를 만들었다" = 로그인하고 저장한 시점 (2026-08-17 검토 2, Day 1 정의 재정의) | `step_count`: 숫자 / `is_public`: boolean / `has_situation`: boolean(상황 상세 유무) | **H-01** |
| EVT-CARD-002 | `card_preview` | `/card` 진입 && 게이트 충족 (SCR-003) — 로그인 전후 무관, 진입당 1회, `?save=1` 복귀 로드 제외 | `step_count` | 보조 퍼널 (preview → create 낙차 = 로그인 벽 비용) |
| EVT-CARD-003 | `card_edit` | `saveWorkflow` 성공 — 수정(`mode=edit`) | `workflow_id` | 보조 (수정 빈도) |
| EVT-SHARE-001 | `card_share` | **소유자가** 자기 카드에서 PNG 다운로드 성공·클립보드 복사 성공 (SCR-004) — 실패 시 미발화 (2026-08-17 검토 3) | `share_method`: `png_download`\|`link_copy` / `workflow_id`: 8자 | **H-02** |
| EVT-SHARE-002 | `card_reshare` | **타인·비로그인**이 남의 카드에서 PNG·링크 복사 성공 (SCR-004) | `share_method` / `workflow_id` | 보조 (라이브러리 확산 기여 — 판정 기준 아님) |
| EVT-AUTH-001 | `login` | `/auth/callback` 성공 후 첫 페이지 로드 1회 | `method`: `github` (GA4 권장 이벤트명 재사용) | 로그인 퍼널 |

역할 주석:
- EVT-BLDR-001: H-01 미달 시 "단계를 담지도 않는다"(가치 전달 실패) vs "담고도 카드를 안 만든다"(빌더 마찰)를 구분. `method=manual`의 `item_name`은 카탈로그 누락 후보 수집 채널
- EVT-CARD-002 → 001 낙차 = **로그인 벽의 비용**. create/preview가 낮으면 v1.x에서 로그인 유도 카피·위치 조정(신기능 아님)
- EVT-SHARE-002 = 타인이 남의 카드를 퍼뜨림 — 라이브러리·상세가 확산에 기여하는 직접 증거 (H-02엔 미포함, 사용자 결정)

## UTM 규격

| 경로 | UTM | 용도 |
|---|---|---|
| `/card-detail/{id}` → 홈 CTA | `utm_source=card&utm_medium=share` | 루프 작동 직접 증거 (H 보조) |
| 라이브러리 → 홈 CTA(빈 상태·헤더) | 내부 이동 — UTM 없음 | 라이브러리 유입은 `page_referrer`로 충분 |
| 런칭 포스트 (Day 18~19) | `utm_source=disquiet` / `geeknews` + `utm_medium=community` | 채널 효과 구분 |

- 내부 링크 UTM은 세션 어트리뷰션을 리셋하지만 의도된 동작 — 카드 경유 재진입을 "card 채널 신규 유입"으로 계수
- v1의 `utm_medium=edit`·`qr`은 폐기(내 카드 수정은 `/me`에서, QR 컷)

## 커스텀 디멘션 등록 (사용자 작업 — GA4 콘솔, Day 15~16까지)

이벤트 범위 디멘션 4개 + 측정항목 1개 (한도 50 중 5):
`method` / `item_category` / `share_method` / `is_public` + 측정항목 `step_count`
(`item_name`·`workflow_id`·`has_situation`는 탐색 분석용 — 등록 보류)

## 킬 크라이테리아 대조표 (판정일 9/17 실행 절차)

| 기준 | 수치 | GA4 확인 방법 |
|---|---|---|
| H-01 생성 전환 ≥15% | `card_create`(신규 저장 성공) 발생 총 사용자 ÷ 전체 총 사용자 | 탐색: 세그먼트 "card_create 발생" 총 사용자 / 전체 |

## 실장 검수 절차 (Day 15~16 — GA4 DebugView)

1. `debug_mode` 활성으로 Happy Path 1회 완주 (비로그인 → 작성 → `/card` → GitHub 로그인 → 저장 → 상세 → PNG·링크)
2. DebugView에서 7종 이벤트 발화 + 파라미터를 위 표와 육안 대조 — 특히 `card_preview`는 로그인 전에, `card_create`는 **저장 성공 후에만** 찍히는지, `login`이 1회만 찍히는지
3. 상세 CTA 클릭 → 리얼타임에서 `session_source=card` 확인
