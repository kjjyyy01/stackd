## 1. 개요
- **목적**: 계정 관리 — 로그아웃 · **탈퇴**(계정+워크플로우 전부 삭제 = 개인정보 삭제권) · 소속·역할 기본값. 라우트 `/settings`, **로그인 필수**(미인증 → ERR-AUTH-001 → `/`), noindex(PRD-04)
- **위치**: 로그아웃·탈퇴는 `/me`에서 분리(기획서 v2 사용자 결정). 경량 화면 — 폼 1개 + 버튼 2개. **탈퇴 확인 입력은 페이지가 아니라 dialog 안에서 받는다**(2026-08-28 사용자 결정 — 파괴적 행동을 한 단계 뒤로 미룬다)
- **컷**: 불가(탈퇴 법적 필수, PRD-14). 소속·역할 기본값 폼만 "소속·역할 필드 컷(4순위)" 시 함께 제거

## 3. 기능 요구사항
### REQ-SET-001: 접근 게이트 (P0)
- **AC-1 (정상)**: Given 로그인 세션, When `/settings` 진입, Then EL-SET-001~005 서버 렌더(계정 표시·기본값 채워짐)
- **AC-2 (검증 실패)**: Given 미로그인·세션 만료, When 진입, Then `/` 리다이렉트 + CPY-COMMON-005 토스트(ERR-AUTH-001)
- **AC-3 (서버 오류)**: Given 세션 조회 실패, Then 미로그인과 동일 처리(안전 측)
- **AC-4 (오프라인)**: 해당 없음 — 서버 렌더 페이지(브라우저 기본 오프라인)

### REQ-SET-002: 소속·역할 기본값 저장 (P0)
- **AC-1 (정상)**: Given 로그인, When 0~20자·BR-003 문자셋 입력 후 저장, Then `updateRoleDefault` → `user_metadata.role_default` 갱신 → 성공 피드백(토스트, CPY 미정의 — 최종 응답) → 이후 SCR-001 빌더 소속·역할 초기값으로 채워짐. 빈 값 저장 = 기본값 해제
- **AC-2 (검증 실패)**: Given 21자+ 또는 허용 외 문자, When 입력, Then 클라 차단 + CPY-CARD-007 인라인(ERR-CARD-003). 서버 재검증 실패도 동일 코드
- **AC-3 (서버 오류)**: Given `updateUser` 실패, Then CPY-SET-005 토스트(ERR-SET-002), 입력값 유지
- **AC-4 (오프라인)**: 서버 액션 실패 → AC-3와 동일(온라인 감지 별도 없음)

### REQ-SET-003: 로그아웃 (P0)
- **AC-1 (정상)**: When EL-SET-004 클릭, Then `signOut` → 세션 쿠키 삭제 → `/` 이동, 헤더 비로그인 상태(CPY-COMMON-006)
- **AC-2 (검증 실패)**: 해당 없음 — 입력 없음
- **AC-3 (서버 오류)**: 해당 없음 — signOut은 쿠키 삭제가 본질, 서버 실패와 무관하게 `/` 이동(PRD-06 실패 코드 없음)
- **AC-4 (오프라인)**: 서버 액션 미도달 → 버튼 pending 해제, 재시도(전용 토스트 없음 — 재시도 비용 0)

### REQ-SET-004: 탈퇴 (P0)
- **AC-1 (정상)**: Given EL-SET-005로 dialog를 열고 확인 입력 = 본인 핸들(§7), When 탈퇴, Then `deleteAccount(confirm)` → 세션 uid 확인 → service role `auth.admin.deleteUser` → workflows cascade(BR-020) → 세션 종료 → `/`. 이후 이전 카드 URL 404(BR-006), 라이브러리·OG 미노출
- **AC-2 (검증 실패)**: Given 입력 ≠ 핸들, Then dialog의 탈퇴 버튼 disabled(액션 미호출). 서버도 세션 핸들과 재대조 — 불일치 시 거부(ERR-SET-001로 반환, §7)
- **AC-3 (서버 오류)**: Given `deleteUser` 예외, Then CPY-SET-004 토스트(ERR-SET-001), 세션·페이지 유지
- **AC-4 (오프라인)**: 서버 액션 실패 → AC-3와 동일
