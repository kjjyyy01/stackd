# 08 도메인 규칙 (BR SSOT)

> 상태 다이어그램: 해당 없음 — 저장되는 상태 객체가 없다 (DB 0). 규칙 전부가 입력 제한 = 구조적 악용 방어 (grill Q4의 수치 확정).

| BR-ID | 규칙 | 강제 지점 | 위반 시 |
|---|---|---|---|
| BR-001 | 스택 항목 ≤ **12개** | 빌더(추가 차단), `/stack`·OG 디코드(초과분 절삭) | `ERR-BLDR-001` |
| BR-002 | 항목 이름 1~**40자** | 직접 입력(차단), 디코드(절삭) | `ERR-BLDR-002` |
| BR-003 | 닉네임 1~**10자** 필수, 허용 문자 = **한글(완성형 가-힣)·영문·숫자·공백·`-_.`** — 이모지·기타 스크립트 금지 (OG 폰트 커버 보장, 2026-08-15 확정) | `/card` 입력(차단·게이트), 디코드(절삭·필터) | `ERR-CARD-001` |
| BR-004 | 카테고리 enum **7종**(`language`·`framework`·`tool` / `skill`·`plugin`·`mcp`·`agent`) 외 무시 — 2026-08-15 피드백 2로 4종→7종 | 직접 입력(선택식이라 원천 차단), 디코드(무시) | 조용히 무시 |
| BR-005 | 파싱 대상 딱 2형식 — `settings.json`(enabledPlugins) / `CLAUDE.md`(카탈로그명 단어 경계 매칭). 그 외 인식 안 함 | SCR-002 추출 로직 | `ERR-PARSE-001` |
| BR-006 | 페이로드 손상·누락 시 홈으로 안내 (에러 화면 아님) | `/stack` 서버 컴포넌트 | `ERR-SHARE-001` |
| BR-007 | BR-001~004·008은 **빌더 입력·`/stack` 디코드·OG 렌더 3곳 전부** 적용 — 한 곳이라도 빠지면 방어 무효 | 공유 유틸 함수 1개로 강제 | — |
| BR-008 | 소속·역할 **선택 입력** 0~20자, 허용 문자 = BR-003 화이트리스트 + `@&` (예: `Dev @ Toss`) — 비우면 카드에 미표시 (2026-08-15 추가) | `/card` 입력(차단), 디코드(절삭·필터) | `ERR-CARD-003` |
| BR-009 | **내 카드 판정** = localStorage `stackd:mycard`를 PRD-05 §URL 페이로드로 인코딩한 값과 URL `s`가 문자열 일치. 일치할 때만 수정 진입, 불일치·저장분 없음 = 타인 카드 → 수정·포크 UI 미노출. `/?s=` 프리필 경로 없음 (2026-08-16 확정) | `/stack` 클라이언트 판정, 홈 진입 | 조용히 미노출 |

- 12개 상한 **수치 고정** (2026-08-14 사용자 확정 — OQ-004 해소. 시안의 12개 레이아웃 검증은 유지)
- XSS: React 텍스트 렌더로 원천 차단 — `dangerouslySetInnerHTML` 금지 (day2 grill Q4)

## 파싱 판별 규칙 (BR-005 세부)

1. JSON 파싱 성공 && `enabledPlugins` 존재 → `settings_json`: 항목명 추출 → 카탈로그 이름 매칭(대소문자 무시), 미매칭분은 `plugin` 카테고리 직접 입력 취급
2. 아니면 카탈로그 이름 단어 경계 매칭 ≥1건 → `claude_md` (카탈로그에 있는 것만 — 자유 텍스트 추측 없음)
3. 둘 다 실패 → `unknown` (추출 0건 폴백)
