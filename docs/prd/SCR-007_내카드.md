## 1. 개요
- **목적**: 내가 만든 워크플로우 관리 — 목록·수정 진입·삭제·공개 전환. 라우트 `/me`, **로그인 필수**, noindex (PRD-04)
- **구현 기능**: F-008 (수정은 SCR-001 `/?edit={id}` 로드, 저장은 SCR-003 — 이 화면은 진입 링크만)
- **없는 것**: 로그아웃·탈퇴는 SCR-008 (사용자 결정) — 설정 링크만 둔다. 타인 카드 포크·프리필 없음 (BR-024)
- **컷 판정**: **수정 진입(EL-ME-006)만 Day 11 컷 2순위** — 컷 시 수정 버튼 제거, 목록·삭제·공개 전환은 유지

## 3. 기능 요구사항
### REQ-ME-001: 인증 게이트 (P0)
- **AC-1 (정상)**: Given 로그인 세션, When `/me` 진입, Then 목록 렌더 (REQ-ME-002)
- **AC-2 (검증 실패)**: Given 비인증, When `/me` 진입, Then `redirect('/?auth=required')` → SCR-001이 CPY-COMMON-005 토스트 (ERR-AUTH-001, PRD-09 — `?auth=failed`와 같은 방식)
- **AC-3 (서버 오류)**: Given 세션 확인 자체가 실패(auth 장애), When 진입, Then 비인증으로 간주 → AC-2와 동일 (재로그인으로 복구)
- **AC-4 (오프라인)**: 해당 없음 — 서버 렌더 페이지, 브라우저 기본 오프라인 화면

### REQ-ME-002: 내 워크플로우 목록 (P0)
- **AC-1 (정상)**: Given 내 워크플로우 ≥1, When 진입, Then `user_id` = 세션인 행만 최신순, 항목마다 카드·제목·배지(공개/비공개, hidden 우선)·액션. 타인 행 미포함(RLS + 명시 필터)
- **AC-2 (검증 실패)**: 해당 없음 — 사용자 입력 없음 (`?page` 정규화는 SCR-006 REQ-LIB-002)
- **AC-3 (서버 오류)**: Given 조회 `error`, When 진입, Then EL-ME-010 — h1 유지, 재시도 링크
- **AC-4 (오프라인)**: 해당 없음 — 서버 렌더

### REQ-ME-003: 삭제 (P0)
- **AC-1 (정상)**: Given 항목, When 삭제 → dialog(CPY-WF-011) 확인, Then `deleteWorkflow(id)` → 성공 시 `revalidatePath('/me')`로 목록에서 제거 (별도 토스트 없음). 버튼 pending 중 재클릭 차단
- **AC-2 (검증 실패)**: Given 소유자 아닌 id(조작), When 호출, Then 서버 액션 소유자 확인 실패 → ERR-ME-001 (CPY-ME-004 토스트), 목록 불변 (BR-024)
- **AC-3 (서버 오류)**: Given DB 실패, When 확인, Then ERR-ME-001 토스트, 항목 유지, 재시도 가능
- **AC-4 (오프라인)**: Given 오프라인, When 확인, Then 서버 액션 호출 실패 → ERR-ME-001 토스트, 항목 유지

### REQ-ME-004: 공개 전환 (P0)
- **AC-1 (정상)**: Given 공개 항목, When 스위치 끔, Then 배지 즉시 비공개(낙관적) → `togglePublic(id, false)` 성공 → 유지 + `revalidatePath('/me')`. 켬은 반대
- **AC-2 (검증 실패)**: Given 소유자 아닌 id, When 호출, Then ERR-ME-001 → 이전 값 롤백 + 토스트
- **AC-3 (서버 오류)**: Given DB 실패, When 토글, Then 롤백 + ERR-ME-001 토스트
- **AC-4 (오프라인)**: Given 오프라인, When 토글, Then 호출 실패 → 롤백 + 토스트

### REQ-ME-005: 수정 진입 (P0 — 컷 2순위)
- **AC-1 (정상)**: Given 항목, When 수정 클릭, Then `/?edit={id}` 이동 → SCR-001이 기존 값 로드 (F-002·BR-019, 소유자 확인은 SCR-001 몫)
- **AC-2 (검증 실패)**: 해당 없음 — 링크 이동뿐 (소유자 아님 처리는 SCR-001)
- **AC-3 (서버 오류)**: 해당 없음 — 이 화면에서 서버 호출 없음
- **AC-4 (오프라인)**: 해당 없음 — 전체 페이지 이동, 브라우저 기본 처리

## 6. 화면 전환
- **진입**: 헤더 "내 카드" 링크(CPY-ME-001, 로그인 상태만) / 직접 URL / SCR-004 소유자 액션 후 복귀(SCR-004 문서 몫)
- **이탈**: `/workflows/{id}` / `/?edit={id}` / `/settings` / `/`
- **리다이렉트**: 비인증 → `/?auth=required` (REQ-ME-001)
- **뒤로가기**: 브라우저 기본. 삭제 후 뒤로가기로 상세 재방문 시 404 (BR-006) — 정상

## 7. 폼 검증
해당 없음 — 텍스트 입력 없음. 삭제 dialog는 확인/취소 버튼만 (확인 문구 입력은 탈퇴 BR-020 전용)

## 8. 데이터 변화
- **조회**: `workflows` where `user_id` = 세션 (PRD-05 RLS "public read"의 소유자 분기)
- **삭제**: `workflows` 행 delete → `feedback.workflow_id` set null (PRD-05 ERD)
- **갱신**: `is_public` + `updated_at` (BR-017). 비공개 전환 시 `/api/og`는 기본 이미지(ERR-OG-001), 기존 캐시는 `v` 버스팅으로 무효 (PRD-06)

## 9. API 호출
| 호출 | 내용 | 실패 |
|---|---|---|
| 읽기 (PRD-06 §읽기 SCR-007) | 세션 클라이언트 `workflows` where `user_id` = 세션 order `created_at desc` `range` 12 (SCR-006 §9와 동일 규칙) | ERR 신규 필요 (§2 EL-ME-010) |
| `deleteWorkflow(id)` | 소유자 확인 → delete → `revalidatePath('/me')` | ERR-ME-001 / 세션 만료 ERR-AUTH-001 |
| `togglePublic(id, is_public)` | 소유자 확인 → update(+`updated_at`) → `revalidatePath('/me')` | ERR-ME-001 / ERR-AUTH-001 |

- 세션 확인은 `/settings`와 공용 헬퍼 1개 (SCR-008과 공유). 클라이언트에서 직접 쓰기 금지 (`00_공통규약.md` §확정 기술 선정)

## 12. 분석 이벤트
커스텀 없음 — `page_view` 자동 (PRD-15). 수정 저장은 SCR-003의 EVT-CARD-002(`mode=edit`) 몫, 삭제·토글은 미측정

## 13. 비기능
- **성능**: LCP ≤2.5초 — 목록 서버 렌더, 아바타 next/image 소형(본인 1종 반복 → 캐시 1회)
- **위생**: h1 1개 · `<main>/<section>/<ul>` · 콘텐츠 서버 렌더. `"use client"`는 스위치(+배지)·삭제 dialog·토스트 아일랜드만
- **메타데이터**: PRD-04 표 `/me` — noindex, canonical 없음
- **보안**: 서버 액션 소유자 확인 2차 (BR-024, PRD-09 IDOR) · 세션 만료 시 쓰기 거부 (PRD-09 §세션 만료) · 캐시 없음(세션 의존 동적 렌더)
