# 17 환경·설정·배포

## 환경변수 (SSOT)

| 변수 | 공개 | 용도 | 어디서 |
|---|---|---|---|
| `NEXT_PUBLIC_SUPABASE_URL` | ✓ | Supabase 프로젝트 URL | 클라·서버 |
| `NEXT_PUBLIC_SUPABASE_ANON_KEY` | ✓ | anon 키 (RLS 하) | 클라·서버 |
| `SUPABASE_SERVICE_ROLE_KEY` | ✗ | feedback 저장·admin·탈퇴 서버 액션 | 서버만 |
| `NEXT_PUBLIC_GA_ID` | ✓ | GA4 측정 ID | 클라 |
| `DISCORD_WEBHOOK_URL` | ✗ | 신고·문의 알림 | 서버만 |
| `ADMIN_USER_IDS` | ✗ | admin uuid 목록(콤마) | 서버만 |
| `NEXT_PUBLIC_SITE_URL` | ✓ | OAuth `redirectTo`·절대 URL (프리뷰에서 다름) | 클라·서버 (없으면 `https://stackd.kr`) |

- `.env.local`은 gitignore. Vercel 프로젝트 env에 Production/Preview 각각 등록. `NEXT_PUBLIC_` 접두사는 위 표의 ✓만 (Day 14 보안 4종 ①)

## 환경 구성

| 환경 | 도메인 | Supabase | GitHub OAuth 콜백 |
|---|---|---|---|
| Production | `stackd.kr` | 프로젝트 1개 (Free) | `https://<project>.supabase.co/auth/v1/callback` (Supabase가 받고 앱 `/auth/callback`으로 리다이렉트) |
| Preview | `*.vercel.app` | **같은 프로젝트** (v1 단일 — 프리뷰에서 만든 데이터가 프로덕션 DB에 들어감. Site URL 허용 목록에 프리뷰 도메인 와일드카드 등록) | 동일 |
| Local | `localhost:3000` | 동일 | Supabase Redirect URLs에 `http://localhost:3000/auth/callback` 추가 |

- 프리뷰·로컬 데이터 오염은 v1 수용 — 시드 3~5장은 프로덕션에서 작성. 판정 후 v2에서 프로젝트 분리(backlog)
- Supabase 대시보드 설정(사용자 작업, Day 4): Auth → Providers → GitHub 활성 + Client ID/Secret / URL Configuration → Site URL·Redirect URLs
