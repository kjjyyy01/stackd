## 1. 개요
- **목적**: 회원 기능(GitHub 로그인·공개 게시물)에 따른 법적 필수 문서 2종 — 개인정보처리방침 `/privacy` · 이용약관 `/terms` (GA4 분석 고지는 처리방침에 통합). 정적 2페이지, 서버 렌더, 각자 index·canonical (PRD-04 §메타데이터)
- **v1 → v2**: v1(page_code PRIVACY, GA4 고지 1페이지) 폐기 — 계정·DB 도입으로 처리방침 전문 + 이용약관 추가. 파일명은 유지
- **제작**: Day 4~11 내, Day 16 필수 게이트(PRD-19). 컷 불가
- **본문 원문**: 이 문서는 **필수 항목 목록**만 정의 — 원문(길이 있는 법적 문서)은 구현 시 작성하며 CPY 사전 대상이 아님. 사실 관계는 PRD-14 §PII 표·PRD-13 표를 따르고, 어긋나면 표가 승

### 2.1 `/privacy` 필수 항목 (PRD-14 §PII 표와 1:1)
| # | 항목 | 내용 근거 (원문 작성 시 이 표만 보고 쓴다) |
|---|---|---|
| 1 | 수집 항목 | GitHub 이메일(auth.users 저장만, 미노출) · GitHub 핸들·아바타(`author_handle`/`author_avatar` 스냅샷, BR-025) · 소속·역할(선택 — `role`) · GA4 행동 데이터·쿠키 · 신고자 id(`feedback.reporter_id`) |
| 2 | 수집·이용 목적 | 로그인·작성자 표기 / 게시물 저장 / 이용 통계·서비스 개선(GA4) / 신고 남용 추적 |

| 4 | 제3자 제공·처리 위탁 | Supabase(Auth·DB) · Google Analytics · Vercel(호스팅) · Slack 웹훅(신고 본문 알림 — PII 없음, BR-021) — PRD-13 표 |
| 5 | 이용자 권리·문의처 | 열람(내 카드·설정)·삭제(탈퇴) · 문의처 = EL-LEGAL-005 |

## 3. 기능 요구사항
### REQ-LEGAL-001: 처리방침·약관 노출 (P0)
- **AC-1 (정상)**: Given 아무 상태(비로그인 포함), When `/privacy` 또는 `/terms` 접속, Then §2.1·§2.2 전 항목이 서버 렌더 HTML로 노출되고 h1 1개, EL-LEGAL-003~005 존재
- **AC-2 (검증 실패)**: 해당 없음 — 입력 없음
- **AC-3 (서버 오류)**: 해당 없음 — 정적 페이지, 데이터 조회 없음
- **AC-4 (오프라인)**: Given 최초 로드 후 오프라인, When 스크롤·상호 링크 클릭, Then 텍스트는 그대로, 링크는 브라우저 기본 오프라인 동작 (별도 처리 없음)

### REQ-LEGAL-002: 전 페이지 도달성 (P0)
- **AC-1 (정상)**: Given 모든 사용자 화면(SCR-001·003·004·006·007·008 + 404), When 푸터 확인, Then `/privacy` `/terms` 링크 존재 (PRD-04 §푸터). `/admin`은 사용자 노출 없음 — 예외
- **AC-2~4**: 해당 없음 — 링크 존재 여부만
