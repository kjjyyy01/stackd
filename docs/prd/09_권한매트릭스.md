# 09 권한 매트릭스 (인가 SSOT)

> 역할 3종: **anon**(비로그인) / **user**(GitHub 로그인) / **admin**(user 중 env `ADMIN_USER_IDS`). user는 리소스별로 owner / other로 갈린다. RLS(PRD-05)와 1:1.

## 리소스 × 역할

| 리소스 · 행위 | anon | user (owner) | user (other) | admin |
|---|---|---|---|---|
| 워크플로우 **읽기** — 공개·!hidden | R | R | R | R |
| 워크플로우 읽기 — 비공개 | ✗ (404) | R | ✗ (404) | R (service role, `/admin`) |
| 워크플로우 읽기 — hidden | ✗ (404) | R (배지) | ✗ (404) | R |
| 워크플로우 **생성** | ✗ → 로그인 유도 (BR-016) | C | — | C (일반 user로서) |
| 워크플로우 수정·삭제·공개 토글 | ✗ | U/D | ✗ (**IDOR 방지**: RLS + 서버 액션 소유자 확인) | ✗ (본인 것만) |
| 워크플로우 `hidden` 토글 | ✗ | ✗ (with check 고정) | ✗ | U (service role) |
| 라이브러리 목록 (공개·!hidden) | R | R | R | R |
| 내 카드 목록 | ✗ → `/` (ERR-AUTH-001) | R (본인) | — | — |
| 초안(localStorage) | 본인 브라우저 | 본인 브라우저 | — | — |
| feedback 생성 (신고·문의) | C (reporter_id null) | C | C | C |
| feedback 읽기·처리 | ✗ | ✗ | ✗ | R/U (service role) |
| `/admin` 진입 | 404 | 404 | 404 | R |
| 설정 (로그아웃·탈퇴·소속 기본값) | ✗ → `/` | R/U/D (본인) | — | — |
| `/api/og?id=` | 공개·!hidden만 렌더, 아니면 기본 이미지 | 동일 (anon 클라이언트 사용 — 소유자 특권 없음) | 동일 | 동일 |
| PNG 다운로드 · 링크 복사 (SCR-004) | ○ (공개 카드) | ○ | ○ | ○ |

- **타인 리소스 열**이 전부 ✗/404인 것이 IDOR 방지의 핵심 — 클라이언트에서 버튼을 숨기는 것과 별개로 서버 액션이 항상 소유자를 확인한다
- admin의 일반 사용은 user와 동일 — 특권은 `/admin`의 service role 액션(BR-022)뿐. 관리 대상 사용자 계정 삭제 등은 v1 없음(Supabase 대시보드도 사용자 결정으로 미사용 → 필요 시 backlog)
- 세션 만료 시: 읽기는 anon으로 계속, 쓰기 시도는 ERR-AUTH-001 → 재로그인 유도 (초안 보존)
