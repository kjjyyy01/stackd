# 01 제품 개요 — MVP 승계 + F/H ID 부여

## 만든 이유 (2026-08-15 추가)

학생·신입·소속 없는 개발자도 개발자들 사이에서 자신을 증명해야 하는 순간이 온다 — 그때마다 이력서를 만들고 건네는 건 과합니다. 격식 없이 **이름과 스택만 가볍게 공유**할 수 있는 매체가 필요했고, Stackd는 그 자리를 카드 한 장으로 채웁니다. 이력서가 "증명"이라면 스택 카드는 "인사"다 — **한 번 만들어 두고 링크 하나로 계속 건넨다.** 만드는 데 시간 제한은 없다 ("30초" 표현은 2026-08-15 피드백 1로 폐기 — 핵심은 속도가 아니라 **한 장을 만들어 계속 쓰는 것**). 새 카드가 필요하면 새로 만들고, 고치고 싶으면 **내 카드를 수정**한다 (F-008 — 만든 브라우저에서, 남의 카드는 수정·포크 불가).

**카드가 담는 스택은 두 축이다 (2026-08-15 피드백 2)**: ① **개발 기술 스택** — React·Next.js·Flutter·TypeScript 등 (`language`/`framework`/`tool`) ② **AI agent 스택** — Claude Code의 skills·plugins·MCP·agents (`skill`/`plugin`/`mcp`/`agent`, v1은 Claude Code 생태계 한정). "AI 스택 카드"의 AI는 ②를 뜻하지만 **②만으로는 명함으로서 정보력이 약하다** — ①이 반드시 함께 들어간다. 카테고리 enum 7종·카드 2단 그룹핑·필터·이벤트 파라미터가 전부 이를 따른다 (PRD-05·08 BR-004·SCR-001·SCR-003·PRD-15).

## 제품 한 줄 (day2 §제품 한 줄 승계)

설정을 붙여넣거나 골라 담으면 공유하고 싶어지는 AI 스택 카드가 나온다 — 한국어 UI, 영어 카드, 비로그인, DB·인증·저장소 0. v1은 Claude Code 생태계 한정.

**포지셔닝 (2026-08-15 확정)**: "내가 쓰는 스택을 카드로" — **개발자들끼리 명함을 주고받는 느낌**. 카드가 주인공이라는 방향의 구체화이며, 카피 톤·카드 디자인·공유 경험 전반이 이 감각을 따른다 (DESIGN.md §카드 디자인 레퍼런스, PRD-11 톤).

**가드 (2026-08-15)**: 명함은 **톤·경험의 은유로 한정**한다. 명함 구성요소의 기능화 — 연락처·**연락처를 담은 QR**·명함첩 등 회수/저장이 필요한 정보 — 는 금지, 전부 backlog (연락처 × URL 영구 인코딩은 아키텍처 모순). **공유 링크를 그려주는 QR(대면 건네기, SCR-003 REQ-CARD-004)은 허용** — 기존 URL의 표현 방식일 뿐 새 정보가 아니다. v1 상한은 **소속·역할 선택 필드(BR-008) + 링크 QR까지**. 명함/공유 카드 타입 선택 모드는 backlog — 판정일 사용 패턴 데이터(`utm_medium=qr` vs `share`)로 결정.
