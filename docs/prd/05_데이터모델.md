# 05 데이터 모델 (스키마 SSOT)

> Supabase Postgres. 데이터는 4곳: **DB 2테이블 + auth.users** / 정적 카탈로그 / 클라이언트 초안(localStorage) / auth user_metadata(설정). URL 페이로드(v1 lz-string)는 **폐기**.

## ERD

```
auth.users 1 ──< workflows (user_id, on delete cascade)
workflows  1 ──< feedback (workflow_id nullable, on delete set null)
```

## `workflows`

| 필드 | 타입 | 제약 | 비고 |
|---|---|---|---|
| `id` | text PK | 16진 8자 `^[0-9a-f]{8}$` (BR-023) | `/workflows/{id}` |
| `user_id` | uuid FK auth.users(id) ON DELETE CASCADE, NOT NULL | 소유자 | RLS 기준 |
| `title` | text NOT NULL | 1~40자 (BR-010) — 이모지·특수문자 허용 (BR-003) | 카드 제목 |
| `situation_short` | text NOT NULL | 1~20자 (BR-011) | 카드 상황 라벨 |
| `situation` | text | 0~1,000자 (BR-012, 선택) | 상세 페이지만 — 줄바꿈 허용 |
| `steps` | jsonb NOT NULL | 배열 2~8 (BR-001). 원소 `{tool:{name(1~40, BR-002), category(enum 7, BR-004)}, note(**1~60 필수**, BR-013), detail(**1~500 필수**, BR-014)}` | 순서 = 배열 순서 |
| `dev_stack` | jsonb NOT NULL default `[]` | 배열 0~4 (BR-015). 원소 `{name, category ∈ language\|framework\|tool}` | 카드 STACK 태그 |
| `author_handle` | text NOT NULL | GitHub `user_name` 스냅샷 (저장·수정 시 갱신) | 카드 `@handle` |
| `author_avatar` | text | GitHub `avatar_url` 스냅샷 | 카드·상세 |
| `role` | text | 0~20자 (BR-008) | 소속/역할 (선택) |
| `accent` | text NOT NULL default `'ink'` | 액센트 슬러그 (DESIGN.md 팔레트 2~3종) | 미인식 → 기본 |
| `is_public` | boolean NOT NULL default true | (BR-017) | 비공개 = 소유자만 |
| `hidden` | boolean NOT NULL default false | admin만 변경 (BR-018) | 모더레이션 |
| `hidden_reason` | text | 1~200자, hidden=true일 때 필수 (BR-018) — 상세 페이지에 **모두에게 표기** | admin 입력 |
| `created_at` / `updated_at` | timestamptz NOT NULL default now() | `updated_at`은 서버 액션에서 갱신 | OG 캐시 버스팅 |

- 인덱스: `(is_public, hidden, created_at desc)` — 라이브러리 목록 / `(user_id, created_at desc)` — 내 카드
- **hidden 행은 RLS로 막지 않는다** — 상세 페이지가 블러 플레이스홀더 + 사유를 렌더해야 하므로(BR-018). 라이브러리·`/api/og`·사이트맵 쿼리가 `hidden = false`를 **명시 필터**한다
- 길이·개수 검증은 **앱 레이어(제한 유틸, BR-007)** — DB CHECK는 `steps` 배열 길이만 (`jsonb_array_length(steps) between 2 and 8`) 방어용

## `auth.users` (Supabase 관리)

- 로그인 = GitHub provider. 사용하는 값: `id`, `user_metadata.user_name`(핸들), `user_metadata.avatar_url`, `email`(**저장만, 어디에도 렌더하지 않음** — PRD-14)
- 설정의 "소속/역할 기본값" = `user_metadata.role_default` (updateUser) — 별도 테이블 없음
- 탈퇴 = `auth.admin.deleteUser` (service role, 서버 액션) → workflows cascade (BR-020)

## RLS (PRD-09 권한 매트릭스와 1:1)

```sql
alter table workflows enable row level security;
create policy "public read"  on workflows for select using (is_public or auth.uid() = user_id);  -- hidden은 앱에서 블러 처리(BR-018)
create policy "owner insert" on workflows for insert with check (auth.uid() = user_id);
create policy "owner update" on workflows for update using (auth.uid() = user_id) with check (auth.uid() = user_id and hidden = (select hidden from workflows w where w.id = workflows.id) and hidden_reason is not distinct from (select hidden_reason from workflows w where w.id = workflows.id));
create policy "owner delete" on workflows for delete using (auth.uid() = user_id);
alter table feedback enable row level security;  -- 정책 없음: anon/authenticated 접근 전면 차단, service role(서버 액션)만
```

- `hidden`·`hidden_reason`은 소유자 update로 바뀌지 않도록 with check에서 고정 — admin 토글은 service role
- `/api/og`·라이브러리는 anon 클라이언트 + `hidden=false` 명시 필터. 상세는 hidden이면 내용 대신 블러 플레이스홀더 + 사유(BR-018)

## 카탈로그 — `data/catalog.json` (정적, v1 그대로)

| 필드 | 타입 | 제약 |
|---|---|---|
| `id` | string | slug, 유일 |
| `name` | string | 1~40자 |
| `category` | enum | 7종 (BR-004) — 개발 `language`·`framework`·`tool` / AI agent `skill`·`plugin`·`mcp`·`agent` |
| `description` | string | 영어 한 줄 |
| `source` | string | 출처 URL |

- 범위: AI agent = Claude Code 생태계 100~200개 + 개발 스택 60~80개 (Day 4 수집, 백엔드와 병행)

## 클라이언트 초안 — localStorage `stackd:draft` (BR-019)

`{v:2, editId?: string, title, situation_short, situation, steps[], dev_stack[], role, accent, is_public}` — 빌더 상태 변경마다 저장, OAuth 왕복·새로고침 후 복원, **저장 성공 시 삭제**. 서버 저장소 아님.
